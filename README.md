# Welcome to Mp3 Championship

So, the FIFA World Cup is over. But all is not lost — you can keep the fun going! Perhaps you have a large collection of MP3 files on your computer (maybe even from the 2000s) that you haven't listened to in years. Now you can do more than just listen — you can run a CHAMPIONSHIP among them, using a real football (or hockey) tournament system.

The idea is simple: you select a directory on your disk containing MP3 files. The program shuffles them (so you can't be sure which track is #1 or #5 from your favorite album), creates a tournament net system where each track "faces" another exactly once (much like a real championship, just without away games). Then, following the bracket, the program runs "matches": each of the two tracks plays for a few seconds (I set 7 seconds for myself, but this is adjustable), and you must choose the winner (Track 1 or Track 2) or make a tie. The winner gets 3 points, the loser gets 0; in case of a draw, each gets 1 point. If you choose the 4th option (listen to the tracks again), in hockey terms that's overtime — the winner now gets 2 points instead of 3 (and there can be many overtimes).

Depending on the number of tracks in your album, the championship can be lengthy, so you can interrupt it at any time by pressing Ctrl+C (or another key combination that forces termination of the Python script on your computer). The program will then display the current standings.

When all matches are played - the program verifies that each track has played exactly n−1 times — the championship is over, and the final standings are displayed.

Now for some details:

1. I spent a long time looking for the optimal approach to generating the tournament schedule. I even left previous match‑selection variants in `champfuncs.py`: first, I simply picked two random tracks that had played the fewest matches; second, I used a "round‑robin" algorithm to generate the schedule and tried to determine the next pair based on the minimum number of played matches among tracks and opponent lists—for an even number of tracks this worked well, but for an odd number, one extra match kept appearing at the end. So I resorted to a third approach: run the round‑robin algorithm before each match and take the i‑th match—this worked well for both even and odd numbers of tracks in the album (championship).

2. Now for the most important part—the match (or duel). A few seconds are randomly selected from each track and played to the listener, who must choose the better track of the match. As you may know, every song is not uniform throughout its duration. Even a great song can have long boring intros, mediocre sections, or tiring endings. Some fragments are highly recognisable, others less so. YOUR mood may change while listening. Take Queen's immortal hit "We Are the Champions"— a great song, but it has a rather long intro, and the truly magical part, IMHO, is the bit about "golden wings of butterfly" and "fairy tales of yesterdays"... Back to reality: the winner gets points, the loser gets none. After each choice, the standings are updated and saved to disk (so that if the championship is interrupted, it resumes with all played matches taken into account).

3. Now a bit about technology and programming. The current version is a kind of "Proof of Concept" — an attempt to evaluate the idea itself. That's why I didn't overload the UI, chose Python as the programming language, and implemented everything in console mode. I used Python 3.8.6 (I didn't think too much about Python version selection, I guess the lower version - the more users (or programmers) can use it). A UI might come later, but for now this is it. For storing track data and current championship status, I used pandas — one table per championship. I chose the `.xls` extension because Microsoft Excel was convenient during development and debugging. Since track titles often contain commas, spaces, and sometimes tabs, I decided to use the pipe symbol `|` as a separator —  characters like that probably won't appear in track and album titles, though... Champ-files get its name from last directory, containing mp3-files. For handling MP3 files, I used two libraries: `mutagen` for reading tags and `pygame` for playing MP3 files and their fragments. For capturing user responses during duels, I chose `pynput`. With standard Python "input", you'd have to press Enter, which is inconvenient. `Pynput` intercepts key presses at a low level, so no Enter is needed. A small configuration of the `pynput` listener helped avoid artefacts from key presses appearing in the console or (even worse) in the program text when running it from an IDE.
